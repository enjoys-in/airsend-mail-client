================================================================================
  CalDev — Frontend API Guide
================================================================================

BASE URL:  http://localhost:8443

================================================================================
  AUTHENTICATION
================================================================================

Frontend auth uses the access_token cookie (set by the mail/auth system).
All requests should include: credentials: "include" in fetch options.

The cookie contains a JWT with: mid (mail_accounts.id), email, name, role.
The server reads tenant_id and user_id from this cookie automatically.

accountId for JMAP = "{tenant_id}:{user_id}" e.g. "85:85"
(Get these from the /jmap/session endpoint after login.)

Example fetch:
  fetch("http://localhost:8443/jmap/api", {
    method: "POST",
    credentials: "include",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ ... })
  })

================================================================================
  RESPONSE FORMATS
================================================================================

REST endpoints (/api/*):
{
  "success": true,
  "message": "description",
  "result": { ... }
}

JMAP endpoints (/jmap/*):
{
  "methodResponses": [ ["MethodName", { ...result }, "callId"] ],
  "sessionState": "abc123"
}

Error (REST):
{
  "success": false,
  "message": "error description",
  "error": { "details": "optional details" }
}

  1. JMAP SESSION (get accountId)
================================================================================

GET /jmap/session

Response (200):
{
  "capabilities": { ... },
  "accounts": {
    "85:85": {
      "name": "user@example.com",
      "isPersonal": true,
      "isReadOnly": false
    }
  },
  "primaryAccounts": {
    "urn:ietf:params:jmap:calendars": "85:85"
  },

  "apiUrl": "http://localhost:8443/jmap/api",
  "state": "a1b2c3d4"
}

Frontend tip: Read primaryAccounts["urn:ietf:params:jmap:calendars"] to get
your accountId. Use it in all JMAP method calls.


================================================================================
  2. JMAP API — How it works
================================================================================

All JMAP calls go through a single endpoint:

POST /jmap/api
Content-Type: application/json

Request format:
{
  "using": ["urn:ietf:params:jmap:calendars"],
  "methodCalls": [
    ["MethodName", { "accountId": "85:85", ...args }, "callId"]
  ]
}

Response format:
{
  "methodResponses": [
    ["MethodName", { ...result }, "callId"]
  ],
  "sessionState": "abc123"
}

You can batch multiple method calls in one request.
"callId" is a client-chosen string to match responses to requests.

================================================================================
  4. Calendar/set — Create / Delete calendars
================================================================================

Create:
{
  "using": ["urn:ietf:params:jmap:calendars"],
  "methodCalls": [
    ["Calendar/set", {
      "accountId": "85:85",
      "create": {
        "temp0": {
          "name": "Work",
          "description": "Work calendar",
          "color": "#EF4444",
          "timezone": "Asia/Kolkata"
        }
      }
    }, "c1"]
  ]
}

Create response:
["Calendar/set", {
  "accountId": "85:85",
  "created": {
    "temp0": { "id": "generated-uuid" }
  },
  "newState": "new-state"
}, "c1"]

"temp0" is your client-chosen temporary ID.
The server returns the real ID in created["temp0"].id.

--------

Delete:
{
  "using": ["urn:ietf:params:jmap:calendars"],
  "methodCalls": [
    ["Calendar/set", {
      "accountId": "85:85",
      "destroy": ["calendar-uuid-to-delete"]
    }, "c2"]
  ]
}

Delete response:
["Calendar/set", {
  "accountId": "85:85",
  "destroyed": ["calendar-uuid-to-delete"],
  "newState": "new-state"
}, "c2"]

================================================================================
  6. CalendarEvent/query — Filter events by date/calendar
================================================================================

{
  "using": ["urn:ietf:params:jmap:calendars"],
  "methodCalls": [
    ["CalendarEvent/query", {
      "accountId": "85:85",
      "filter": {
        "calendarId": "calendar-uuid",
        "after": "2026-03-01T00:00:00Z",
        "before": "2026-04-01T00:00:00Z"
      },
      "position": 0,
      "limit": 50
    }, "q0"]
  ]
}

Filter fields (all optional):
  calendarId   string   filter by calendar UUID
  after        string   ISO 8601 — events starting after this time
  before       string   ISO 8601 — events starting before this time

Response returns event IDs (use CalendarEvent/get to fetch full objects):
["CalendarEvent/query", {
  "accountId": "85:85",
  "queryState": "abc123",
  "position": 0,
  "ids": ["event-uuid-1", "event-uuid-2", "event-uuid-3"],
  "total": 3
}, "q0"]

================================================================================
  8. CalendarEvent/changes — Sync changes since last state
================================================================================

Use this for incremental sync. Save the "state" from previous responses
and pass it as "sinceState" to get only what changed.

{
  "using": ["urn:ietf:params:jmap:calendars"],
  "methodCalls": [
    ["CalendarEvent/changes", {
      "accountId": "85:85",
      "sinceState": "previous-state-token"
    }, "ch0"]
  ]
}

Response:
["CalendarEvent/changes", {
  "accountId": "85:85",
  "oldState": "previous-state-token",
  "newState": "new-state-token",
  "hasMoreChanges": false,
  "created": ["new-event-uuid"],
  "updated": ["modified-event-uuid"],
  "destroyed": ["deleted-event-uuid"]
}, "ch0"]


================================================================================
  9. RSVP — Respond to event invitations
================================================================================

POST /api/scheduling/rsvp
Content-Type: application/json

Request:
{
  "event_uid": "event-uid@caldev",
  "response": "ACCEPTED",
  "comment": "I'll be there!"
}

Valid response values:
  ACCEPTED, DECLINED, TENTATIVE
  (shortcuts: accept/yes, decline/no, maybe)

Response (200):
{
  "success": true,
  "message": "RSVP recorded. Reply sent to organizer.",
  "result": {
    "event_uid": "event-uid@caldev",
    "attendee": "user@example.com",
    "response": "ACCEPTED"
  }
}


================================================================================
  10. CALENDAR SUBSCRIPTIONS (Import external calendars)
================================================================================

GET /api/subscriptions/
List all subscriptions.

Response (200):
{
  "success": true,
  "message": "subscriptions retrieved",
  "result": {
    "subscriptions": [
      {
        "id": "uuid",
        "calendar_id": "uuid",
        "source_type": "google",
        "source_url": "https://calendar.google.com/calendar/ical/.../basic.ics",
        "display_name": "Indian Holidays",
        "color": "#10B981",
        "is_enabled": true,
        "sync_interval": 3600,
        "last_synced_at": "2026-03-10T12:00:00Z",
        "events_count": 535,
        "last_error": ""
      }
    ]
  }
}

--------

POST /api/subscriptions/
Create a new subscription.

Request:
{
  "source_url": "https://calendar.google.com/.../basic.ics",
  "display_name": "Indian Holidays",
  "color": "#10B981",
  "sync_interval": 3600
}

Fields:
  source_url        REQUIRED   ICS feed URL
  display_name      optional   default: "Imported Calendar"
  color             optional   default: "#6B7280"
  source_type       optional   default: "ics_url" (auto-detects google/outlook)
  auth_type         optional   "none" | "basic" | "bearer" | "api_key"
  auth_credentials  optional   credentials string for auth_type
  sync_interval     optional   default: 3600 (seconds, min 300)
  calendar_id       optional   auto-creates a read-only calendar if empty

Response (201):
{
  "success": true,
  "message": "Subscription created. First sync is running in the background.",
  "result": {
    "subscription": { ... },
    "calendar_id": "uuid"
  }
}

--------

PUT /api/subscriptions/:id
Update subscription (all fields optional).

Request:
{
  "display_name": "New Name",
  "color": "#EF4444",
  "is_enabled": false,
  "sync_interval": 7200
}

--------

DELETE /api/subscriptions/:id?delete_calendar=true
Delete subscription. Add ?delete_calendar=true to also delete the calendar.

Response: 204 No Content

--------

POST /api/subscriptions/:id/sync
Trigger immediate sync.

Response (200):
{
  "success": true,
  "message": "Sync completed successfully",
  "result": {
    "subscription": { ... updated subscription ... }
  }
}

================================================================================
  FRONTEND ROUTE SUMMARY
================================================================================

Method  Path                         Auth     Format   Description
──────  ────                         ────     ──────   ───────────
GET     /health                      None     JSON     Health check
GET     /jmap/session                Cookie   JSON     Get accountId & session
POST    /jmap/api                    Cookie   JSON     All calendar CRUD operations
POST    /api/scheduling/rsvp         Cookie   JSON     RSVP to event invitation
GET     /api/subscriptions/          Cookie   JSON     List external subscriptions
POST    /api/subscriptions/          Cookie   JSON     Add external calendar
PUT     /api/subscriptions/:id       Cookie   JSON     Update subscription
DELETE  /api/subscriptions/:id       Cookie   JSON     Delete subscription
POST    /api/subscriptions/:id/sync  Cookie   JSON     Trigger manual sync

Note: /dav/* routes are for native CalDAV clients (Apple Calendar, Thunderbird).
      Do NOT use them from the web frontend — use /jmap/api instead.
