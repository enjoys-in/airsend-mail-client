CalDev — API Context for UI Development
========================================

What is CalDev?
A CalDAV + JMAP calendar server written in Go (Fiber), PostgreSQL, Valkey.
Part of a larger ecosystem (mail system). Shares public.users table and JWT auth.

Tech Stack: Go 1.24, Fiber v2.52.12, PostgreSQL 16, Valkey 8
Server port: 8443
Multi-tenant: all data scoped by tenant_id + user_id

================================================================================
STANDARD RESPONSE ENVELOPE
================================================================================

Every REST API response follows this structure:

Success:
{
  "success": true,
  "message": "human-readable message",
  "result": { ... data ... }
}

Error:
{
  "success": false,
  "message": "human-readable error message",
  "result": null,
  "error": {
    "details": "additional detail if available"
  }
}

Created (HTTP 201):
{
  "success": true,
  "message": "resource created message",
  "result": { ... data ... }
}

Delete success: HTTP 204 (no body)

Note: JMAP endpoints (/jmap/*) follow RFC 8620 response format, not this envelope.
Note: CalDAV endpoints (/dav/*) use WebDAV XML responses per RFC 4791.
Note: ICS feed endpoints return text/calendar, not JSON (except FeedIndex).

================================================================================
AUTHENTICATION
================================================================================

Two methods, both work on all endpoints:

1. JWT Bearer (frontend should use this)
   Header: Authorization: Bearer <jwt-token>
   JWT claims: sub (user UUID), tid (tenant UUID), email
   Validated with shared AUTH_JWT_SECRET + AUTH_JWT_ISSUER

2. Basic Auth (for CalDAV clients, ICS feeds)
   Header: Authorization: Basic base64(email:app-password)
   Uses app passwords (not login password), stored bcrypt-hashed

Test Credentials (dev/seed):
  Email:       test@caldev.local
  App password: testpassword
  Tenant ID:   b0000000-0000-0000-0000-000000000001
  User ID:     a0000000-0000-0000-0000-000000000001

================================================================================
CORS
================================================================================

All endpoints return:
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS, PROPFIND, ...
  Access-Control-Allow-Headers: Authorization, Content-Type, Depth, If-Match, ...
  Access-Control-Expose-Headers: ETag, DAV, Allow, Lock-Token

3. Calendars & Events (via JMAP) — /jmap/
--------------------------------------------------------------------------------
Auth: JWT Bearer
NOTE: JMAP follows RFC 8620 response format, NOT the standard envelope above.

GET /jmap/session
  Returns JMAP session resource.

  Response:
  {
    "capabilities": {
      "urn:ietf:params:jmap:core": { ... },
      "urn:ietf:params:jmap:calendars": { ... }
    },
    "accounts": {
      "{tenant}:{user}": {
        "name": "user@example.com",
        "isPersonal": true,
        "isReadOnly": false
      }
    },
    "primaryAccounts": {
      "urn:ietf:params:jmap:calendars": "{tenant}:{user}"
    },
    "username": "user@example.com",
    "apiUrl": "http://localhost:8443/jmap/api",
    "state": "a1b2c3d4"
  }

POST /jmap/api
  JMAP method calls (batched).

  Request body:
  {
    "using": ["urn:ietf:params:jmap:core", "urn:ietf:params:jmap:calendars"],
    "methodCalls": [
      ["Calendar/get", {"accountId": "{tenant}:{user}"}, "c0"],
      ["CalendarEvent/get", {"accountId": "{tenant}:{user}", "ids": ["event-uuid"]}, "e0"],
      ["CalendarEvent/query", {"accountId": "{tenant}:{user}", "filter": {"calendarIds": ["cal-uuid"]}}, "q0"]
    ]
  }

  Response:
  {
    "methodResponses": [
      ["Calendar/get", {"accountId": "...", "state": "...", "list": [...]}, "c0"],
      ["CalendarEvent/get", {"accountId": "...", "state": "...", "list": [...]}, "e0"]
    ],
    "sessionState": "a1b2c3d4"
  }

  Supported JMAP methods:
    Calendar/get           — Get calendars
    Calendar/set           — Create/update/delete calendars
    CalendarEvent/get      — Get events by ID
    CalendarEvent/set      — Create/update/delete events
    CalendarEvent/query    — Query events with filters
    CalendarEvent/changes  — Get changes since a sync state

  Calendar/set example (create):
  {
    "using": [...],
    "methodCalls": [
      ["Calendar/set", {
        "accountId": "{tenant}:{user}",
        "create": {
          "cal1": {"name": "Work", "color": "#EF4444"}
        }
      }, "c0"]
    ]
  }

  CalendarEvent/set example (create):
  {
    "using": [...],
    "methodCalls": [
      ["CalendarEvent/set", {
        "accountId": "{tenant}:{user}",
        "create": {
          "e1": {
            "calendar_id": "cal-uuid",
            "summary": "Team Meeting",
            "description": "Weekly standup",
            "location": "Room 42",
            "dtstart": "2026-02-26T14:00:00Z",
            "dtend": "2026-02-26T15:00:00Z",
            "all_day": false,
            "status": "CONFIRMED",
            "attendees": [
              {"email": "jane@example.com", "display_name": "Jane", "role": "REQ-PARTICIPANT", "rsvp": true}
            ],
            "categories": ["Work"]
          }
        }
      }, "e0"]
    ]
  }

  CalendarEvent/set example (update):
  {
    "using": [...],
    "methodCalls": [
      ["CalendarEvent/set", {
        "accountId": "{tenant}:{user}",
        "update": {
          "event-uuid": {
            "summary": "Updated Title",
            "dtstart": "2026-02-27T10:00:00Z"
          }
        }
      }, "e0"]
    ]
  }

  CalendarEvent/set example (delete):
  {
    "using": [...],
    "methodCalls": [
      ["CalendarEvent/set", {
        "accountId": "{tenant}:{user}",
        "destroy": ["event-uuid-1", "event-uuid-2"]
      }, "e0"]
    ]
  }

  CalendarEvent/query example (filter by calendar + date range):
  {
    "using": [...],
    "methodCalls": [
      ["CalendarEvent/query", {
        "accountId": "{tenant}:{user}",
        "filter": {
          "calendarIds": ["cal-uuid"],
          "after": "2026-02-01T00:00:00Z",
          "before": "2026-03-01T00:00:00Z"
        }
      }, "q0"]
    ]
  }

  CalendarEvent/changes example:
  {
    "using": [...],
    "methodCalls": [
      ["CalendarEvent/changes", {
        "accountId": "{tenant}:{user}",
        "sinceState": "previous-state-token"
      }, "ch0"]
    ]
  }

          "source_type": "google",
          "source_url": "https://calendar.google.com/...",
          "display_name": "Indian Holidays",
          "color": "#10B981",
          "auth_type": "none",
          "is_enabled": true,
          "sync_interval": 3600,
          "last_synced_at": "2026-02-26T12:00:00Z",
          "last_etag": "",
          "last_error": "",
          "error_count": 0,
          "events_count": 535,
          "created_at": "2026-02-26T10:00:00Z",
          "updated_at": "2026-02-26T12:00:00Z"
        }
      ],
      "help": {
        "google_calendar": "Settings → calendar → Integrate → Secret address in iCal format",
        "outlook": "Settings → Calendar → Shared calendars → Publish a calendar → ICS link",
        "any_ics": "Any public or authenticated .ics feed URL"
      }
    }
  }

POST /api/subscriptions/
  Create a new subscription. Auto-creates a read-only calendar and triggers first sync.

  Request body:
  {
    "source_url": "https://calendar.google.com/calendar/ical/.../basic.ics",
    "display_name": "Indian Holidays",
    "color": "#10B981",
    "source_type": "ics_url",
    "auth_type": "none",
    "auth_credentials": "",
    "sync_interval": 3600,
    "calendar_id": ""
  }

  Fields:
    source_url       (required)  — The ICS feed URL
    display_name     (optional)  — Default: "Imported Calendar"
    color            (optional)  — Hex color, default: "#6B7280"
    source_type      (optional)  — "ics_url" (auto-detects "google"/"outlook" from URL)
    auth_type        (optional)  — "none", "basic", "bearer", "api_key"
    auth_credentials (optional)  — Credentials for authenticated feeds
    sync_interval    (optional)  — Seconds, default: 3600, minimum: 300
    calendar_id      (optional)  — Link to existing calendar (empty = auto-create)

  Response (201):
  {
    "success": true,
    "message": "Subscription created. First sync is running in the background.",
    "result": {
      "subscription": { ... },
      "calendar_id": "uuid"
    }
  }

GET /api/subscriptions/:id
  Get a single subscription.

  Response:
  {
    "success": true,
    "message": "subscription retrieved",
    "result": {
      "subscription": { ... }
    }
  }

  Error (404):
  {
    "success": false,
    "message": "subscription not found",
    "result": null,
    "error": {}
  }

PUT /api/subscriptions/:id
  Update a subscription. All fields optional (partial update).

  Request body:
  {
    "display_name": "New Name",
    "color": "#EF4444",
    "source_url": "https://new-url.ics",
    "auth_type": "basic",
    "auth_credentials": "user:pass",
    "is_enabled": false,
    "sync_interval": 7200
  }

  Response:
  {
    "success": true,
    "message": "subscription updated",
    "result": {
      "subscription": { ... }
    }
  }

DELETE /api/subscriptions/:id
  Delete a subscription. Optionally delete the linked calendar + events.
  Query params: ?delete_calendar=true

  Response: 204 No Content

POST /api/subscriptions/:id/sync
  Trigger an immediate sync. Runs synchronously.

  Response:
  {
    "success": true,
    "message": "Sync completed successfully",
    "result": {
      "subscription": {
        "last_synced_at": "2026-02-26T12:30:00Z",
        "events_count": 535,
        "error_count": 0,
        "last_error": ""
      }
    }
  }

  Error (500):
  {
    "success": false,
    "message": "sync failed",
    "result": null,
    "error": {
      "details": "HTTP 404: Not Found"
    }
  }

5. Scheduling (RSVP / iMIP) — /api/scheduling/
--------------------------------------------------------------------------------
Auth: JWT Bearer

POST /api/scheduling/incoming
  Inbound iMIP — mail system webhook. When someone replies to a calendar invite
  email (Accept/Decline/Tentative), the mail system POSTs the ICS body here.

  Accepts two content types:
    application/json:
    {
      "tenant_id": "uuid",
      "ics": "BEGIN:VCALENDAR\r\nMETHOD:REPLY\r\n...",
      "sender_email": "attendee@example.com"
    }

    text/calendar:
    Raw ICS body + X-Tenant-ID header

  Response (REPLY processed):
  {
    "success": true,
    "message": "Attendee status updated successfully",
    "result": {
      "method": "REPLY",
      "event_uid": "event-uid@caldev",
      "attendee": "attendee@example.com",
      "partstat": "ACCEPTED"
    }
  }

  Response (CANCEL acknowledged):
  {
    "success": true,
    "message": "Cancellation acknowledged",
    "result": {
      "method": "CANCEL",
      "event_uid": "event-uid@caldev"
    }
  }

  Response (REQUEST acknowledged):
  {
    "success": true,
    "message": "Invitation received",
    "result": {
      "method": "REQUEST",
      "event_uid": "event-uid@caldev"
    }
  }

  Error (400):
  {
    "success": false,
    "message": "failed to parse scheduling ICS",
    "result": null,
    "error": {
      "details": "no METHOD found in ICS"
    }
  }

POST /api/scheduling/rsvp
  User RSVP response. Authenticated user responds to an event invitation.
  Updates attendee PARTSTAT and sends a REPLY email to the organizer.

  Request body:
  {
    "event_uid": "event-uid@caldev",
    "response": "ACCEPTED",
    "comment": "Looking forward to it!"
  }

  Valid response values: ACCEPTED, DECLINED, TENTATIVE
  Also accepts: accept, decline, maybe, yes, no

  Response:
  {
    "success": true,
    "message": "RSVP recorded. Reply sent to organizer.",
    "result": {
      "event_uid": "event-uid@caldev",
      "attendee": "user@example.com",
      "response": "ACCEPTED"
    }
  }

  Error (404):
  {
    "success": false,
    "message": "event not found or you are not an attendee",
    "result": null,
    "error": {
      "details": "no event found with UID event-uid@caldev"
    }
  }

6. ICS Feeds — /feeds/

These return text/calendar (ICS), not JSON — for external clients.

GET /feeds/{tenant}/{user}/
  JSON index of available feeds.

  Response:
  {
    "success": true,
    "message": "feeds retrieved",
    "result": {
      "feeds": [
        {

          "name": "Personal",
          "description": "My default calendar",
          "color": "#4F46E5",
          "feed_url": "/feeds/{tenant}/{user}/{calendar_id}.ics"
        }
      ],
      "help": {
        "outlook": "File → Account Settings → Internet Calendars → New → paste the feed_url",
        "google": "Other calendars (+) → From URL → paste the feed_url",
        "apple": "File → New Calendar Subscription → paste the feed_url"
      }
    }
  }

GET /feeds/{tenant}/{user}/{calendar}.ics
  Single calendar ICS feed. Supports ETag + If-None-Match (304 Not Modified).
  Response: text/calendar; charset=utf-8

GET /feeds/{tenant}/{user}/all.ics
  Merged ICS of all calendars. Supports ETag + If-None-Match.
  Response: text/calendar; charset=utf-8

================================================================================
HTTP STATUS CODES
================================================================================

200 — Success
201 — Created
204 — No Content (successful delete)
304 — Not Modified (ETag match on feeds)
400 — Bad Request (validation error)
401 — Unauthorized (missing or invalid credentials)
404 — Not Found
429 — Too Many Requests (rate limited)
500 — Internal Server Error

================================================================================
UI FEATURE SUGGESTIONS
================================================================================

- Calendar sidebar: list calendars (color dot, name, visibility toggle, read-only badge for imported)
- Month/week/day views: events from CalendarEvent/query with date filters
- Event create/edit modal: summary, description, location, dtstart/dtend, all_day, recurrence, attendees, categories, status
- Calendar CRUD: create/rename/recolor/delete calendars via Calendar/set
- RSVP UI: show pending invitations, accept/decline/maybe buttons → POST /api/scheduling/rsvp
- External subscriptions page: list, add (paste ICS URL), sync status, event count, error display, manual sync button, enable/disable toggle
- App passwords page: list/create/delete, show feed URLs for Outlook/Google setup
- Settings: timezone, default calendar
